# 公開・接続の受け入れ確認

PR #2（バックエンド）→ #3（ビューア）の順でマージした後に使う手順です。本番のリソース作成、シークレット登録、デプロイ、Grokへの接続登録は所有者が行います。この手順やCIが本番環境を自動変更することはありません。

## 1. 公開前

- [ ] 両PRのCIが成功し、レビュー・マージが済んでいる。
- [ ] `npm ci` → `npm run check` → `npm run build` が成功する。
- [ ] `wrangler.jsonc` のD1 ID・リソース名が所有する環境を指している。
- [ ] Workers Free・D1・R2・Browser Renderingの利用枠を確認した。PNG用ブラウザはFreeで1日10分・同時3ブラウザ。
- [ ] 32文字以上の `ADMIN_TOKEN`、`VIEWER_PASSWORD`、`SESSION_SECRET` を別々のランダム値で設定した。実値はGitやPRに記載しない。
- [ ] READMEの手順で本番D1へマイグレーションを適用し、デプロイした。
- [ ] HTTPSのWorker URLを確認した。

## 2. Bot用トークン

READMEの `/admin/tokens` APIでテスト用トークンを発行し、値を安全に保管します。管理者トークンをBotの接続設定に流用しないでください。テスト用トークンのIDも控え、確認後に失効できます。

## 3. 自動スモークテスト

このコマンドは**対象環境に1ファイル・1ページ・モバイル/PCの2画面・画像を作成し、その画面を変更します**。ファイル名は `Connection check <日時>` で、実行後も残ります。既存ファイルは変更しません。実行は明示的な操作に限り、CIから本番へは実行しません。

Node.js 24以上で、環境変数を設定して実行します。トークンやパスワードをコマンド引数に渡す必要はありません。シークレット値はシェルの安全な入力やシークレット管理から設定してください。

```sh
# 必須: 対象のorigin URLと発行したBotトークン
# CANVAS_BASE_URL=https://<Workerのホスト>
# CANVAS_MCP_TOKEN=<安全な方法で環境変数へ設定>

# 任意: 設定するとログイン後の閲覧も検証する
# CANVAS_VIEWER_PASSWORD=<安全な方法で環境変数へ設定>

npm run smoke
```

`CANVAS_BASE_URL` を省略すると `http://localhost:8787` になります。リモート環境はHTTPS必須です。ローカルでPNGまで確認するにはBrowser Renderingが動く実行環境が必要です。CIではリモートのブラウザ起動を実際のローカルChromiumに置き換え、同じコマンドを一時的なローカルHTTPサーバーに接続して検証しています。

実行内容:

1. 未認証のMCP・閲覧データアクセスが拒否されることを確認。
2. 公式MCP SDKのクライアントで接続し、20ツールを列挙。
3. MCPだけで390×844と1440×900の画面を作成。色・文字・余白・角丸トークン、group、text、画像を使用。
4. PNG image contentの形式・寸法を確認し、同じ版を再取得して一致を確認。
5. テキストを変更し、PNGが変わることを確認。
6. 色トークンを変更し、PNGが変わることを確認。
7. ファイル・変更履歴を再取得し、部分更新で座標が維持されたことを確認。
8. `CANVAS_VIEWER_PASSWORD` があれば、ログインCookie、ファイル一覧、両プレビューの変更反映、画像、PNG用の公開フォント、ログアウトを確認。

`CANVAS_VIEWER_PASSWORD` がない場合、閲覧の確認は `SKIP` と表示します。その場合は閲覧の受け入れ条件を検証済みにはできません。

成功時は6枚のPNGと `result.json` を一時ディレクトリへ保存します。場所は最後に表示されます。`CANVAS_SMOKE_OUTPUT_DIR` を設定すると保存先を指定できます。PNGには作成した画面、JSONにはファイルID・画面情報・検証結果を保存します。認証情報は保存しません。出力にはデザイン内容が含まれるため、共有先には注意してください。

失敗時は終了コード1で停止し、作成済みのファイルIDがあれば表示します。失敗後のファイル・画像は残ります。トークン単位で毎分60リクエスト、D1変更は共有で毎分12回の制限があるため、短時間に繰り返して429になった場合は次の分まで待ってください。ブラウザの無料枠切れ・同時実行上限もCloudflareで確認します。自動再試行は行いません。

## 4. スマホ実機

- [ ] Worker URLをスマホで開き、閲覧パスワードでログイン。
- [ ] スモークテストで作成したファイル→Acceptanceページ→mobileへ進む。
- [ ] 「更新済み」と変更後のブランド色が表示される。
- [ ] desktopへ切り替え、「画面に合わせる」とズーム・スクロールを確認。
- [ ] 出力したPNGとプレビューを見比べ、日本語・画像・groupの表示が一致する。
- [ ] MCPで追加のテキスト変更を行い、10秒後か手動更新で反映を確認。
- [ ] ログアウト後、閲覧データを取得できないことを確認。

## 5. Grok Bot

- [ ] カスタムMCPコネクタへ `https://<Workerのホスト>/mcp` とBot用Bearerを登録。
- [ ] Grokからツール一覧を取得できる。
- [ ] Grokから別のテスト用ファイルを作り、モバイル/PCの2画面を描く。
- [ ] `render_frame` でPNGが返り、Grokが確認できる。
- [ ] Grokで画面を修正し、スマホとPNGの両方へ反映される。
- [ ] テスト用トークンを失効し、以後の接続が拒否される。

スモークテストはMCP SDKの接続を検証します。Grok側のプラン・Bearer付きカスタムコネクタ対応・実アカウントでの接続確認は、このチェックで別途実施してください。
